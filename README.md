# Refactoring Python code smells with LLMs

Code of an empirical study that compares the quality of Python code smell
refactorings generated by three local language models. The smells are those
detected by Pysmell (Chen et al.); phase 1 covers Long Method (LM), Long
Parameter List (LPL), Long Lambda Function (LLF) and Multiply-Nested
Container (MNC).

## Evaluated models

Three open-weight models, one per vendor, running locally through
[Ollama](https://ollama.com) 0.33.2, all Instruct and with the same
quantization (Q4_K_M):

| Model | Ollama tag |
|---|---|
| Qwen2.5-Coder-7B-Instruct | `qwen2.5-coder:7b-instruct-q4_K_M` |
| DeepSeek-Coder-6.7B-Instruct | `deepseek-coder:6.7b-instruct-q4_K_M` |
| Llama 3 8B Instruct | `llama3:8b-instruct-q4_K_M` |

Same parameters for all (`config.yaml`): temperature 0.5, `num_ctx` 8192,
`num_predict` 4096, `top_k` 0, `top_p` 1.0, `min_p` 0, `repeat_penalty` 1.0
and seeds 42, 43 and 44 for the three runs. The digest of each model is
pinned in `config.yaml`; the client aborts if the installed model differs.

## Design

- **Instances (phase 1):** the snippets of the Zhang et al. (2024) dataset,
  grouped by the function that contains the smell: 65 instances, 59 after
  the exclusions made during adaptation (LM 9, LPL 19, LLF 11, MNC 20).
  Reasons in `instances/excluded.csv`.
- **Instances (phase 2):** functions detected by the ported Pysmell in the
  repositories of the PyExamine corpus (Zenodo 10.5281/zenodo.14066039).
- **Prompts:** three techniques (Role Prompting, Few-Shot,
  Chain-of-Thought), with the same task core and only the technique layer
  varying.
- **Generation:** instances x 3 models x 3 techniques x 3 runs, each call in
  a fresh context.
- **Validation:** each refactoring goes through the pytest tests of its
  instance (was behavior preserved?) and through Pysmell (was the smell
  removed?).
- **Metrics:** only for refactorings that preserved behavior: Radon (CC,
  MI), Pylint and Pysmell, on the original and on the refactored code.

## Repository layout

| Step                            | Where                                   |
|---------------------------------|-----------------------------------------|
| Input dataset (phase 1)         | `data/dataset_zhang/` (download, see below) |
| Corpus (phase 2)                | `data/pyexamine/` (extraction, detection and sampling) |
| Smell detection                 | `pysmell/` (Pysmell ported to Python 3) |
| Instance selection              | `data/selection/`                       |
| Adapted units + tests           | `instances/<SMELL>/<ID>/`               |
| Instance checklist              | `adaptation/checklist.py`, `instances/checklist.csv` |
| Context window                  | `adaptation/measure_window.py`, `instances/window.csv` |
| Prompts (Role, Few-Shot, CoT)   | `prompts/`, built by `generation/prompts.py` |
| Generation                      | `generation/`, output in `results/generations/` |
| Code extraction                 | `generation/extract.py`, output in `results/generations/<phase>/_extracted/` |
| Functional and smell validation | `validation/`, output in `results/validation/` |
| Metrics (Radon/Pylint/Pysmell)  | `metrics/`, output in `results/metrics/` |
| Comparative analysis            | `analysis/`                             |
| Pilot round                     | `results/pilot/` (frozen, see below)    |

Each instance has `<ID>.py` (the unit, which is what goes into the prompt),
`test_<ID>.py` (three tests: typical, edge and invalid) and `origin.json`
(provenance and adaptations, never sent to the model).

## Pilot round

`results/pilot/` holds a complete earlier round of phase 1 (generation,
extraction, validation and a metrics test), produced with earlier versions
of the prompts and of the units. It is kept unchanged, with its original
file and column names, as a record of the pilot; the git tag
`rodada1-piloto` points to the code that produced it. Paths stored inside
its CSVs are relative to the phase folder (`results/pilot/geracoes/fase1/`).

## Reproduction

Requirements: Python 3.14 and Ollama 0.33.2 with the three models above
pulled (`ollama pull <tag>`).

The input dataset is not part of the repository, because it is third-party
code. Download it from <https://doi.org/10.5281/zenodo.13335000> and unzip
it into `data/dataset_zhang/`, so that `data/dataset_zhang/dataset/files/`
exists. Details in `pysmell/README.md`.

```bash
pip install -r requirements.txt

python -m pysmell.validate_port            # checks the Pysmell port (83/83 snippets)
python -m data.selection.select            # builds the list of phase 1 instances
python -m data.pyexamine.extract_py        # downloads only the .py files of the PyExamine corpus
python -m data.pyexamine.detect            # runs Pysmell on that corpus
python -m data.selection.select --phase 2  # Zhang instances of the phase 2 smells
python -m data.pyexamine.sample            # filters and samples the phase 2 instances
python -m adaptation.checklist             # checklist of every instance
pytest instances                           # tests of every instance
python -m adaptation.measure_window        # prompt size of each instance in each model

python -m generation.smoke_test --dry-run  # checks config, Ollama up and digests
python -m generation.smoke_test            # one short call to each model
python -m generation.generate --dry-run    # checks the environment and counts what is missing
python -m generation.generate              # whole phase, resumes where it stopped
python -m generation.extract               # extracts the code from the raw responses

python -m validation.check LLF-01 <file>   # preserved? smell removed?
python -m validation.validate              # validation of the whole phase
python -m metrics.measure                  # metrics of the whole phase
```

Metric values depend on the tool versions, pinned in `requirements.txt`.

On determinism: even with fixed seeds and parameters, the output may change
with another Ollama version, another driver or another GPU, and DeepSeek
runs partly on the CPU (about 16%), which rounds differently from the GPU.
That is why every raw response is archived in `results/generations/`,
immutably, with the full prompt, the parameters, the model served (tag and
digest), the Ollama version and the GPU usage. Those records are the
evidence, not the promise of regeneration.

## Data provenance

The phase 1 instances derive from the Zhang et al. (2024) dataset, adapted
into executable units. The Few-Shot examples were written for this project
and do not come from the dataset.

## Code authorship

The adapted units and tests were written by the author with the support of
language models. The refactorings evaluated in `results/` were generated
exclusively by the three models under evaluation, and are recorded with the
model of origin and the parameters used.
